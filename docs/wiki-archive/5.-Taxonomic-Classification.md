## 1. Mapping 

As the first step of taxonomic classification, we need to map our preprocessed and prefiltered data (ending with the suffix ``` .euk.fastq.gz ``` ) against the eukaryotic reference databases. Our database is seperatede into multiple different chunks an example command is below: 

```
for db in {1..129}; do
    cat "$SAMPLE_LIST" | parallel -j "$THREADSP" "bowtie2 --threads $THREADS -k 1000 -t \
      -x $DB_PATH.$db.fas.gz -U $EUK_OUT/{}.euk.fastq.gz --no-unal --mm -t | \
      samtools view -bS - > $EUK_OUT/{}.euk.$db.bam 2> $EUK_OUT/eukaryota.$db.log.txt"
    check_success "Mapping to eukaryote database part $db"
done
``` 
Function: 
  - ```--threads ``` number of allocated threads
  - ``` -k ``` number of valid alignments per read, sorted based on alignment score (Note: every alignment after the first has a SAM 'secondary' bit (which equals 256) set in its FLAGS field (see: https://bowtie-bio.sourceforge.net/bowtie2/manual.shtml) 
  - ```-t ``` wall-clock time output
  - ```-x ``` bowtie2 index prefix
  - ``` -U ``` FASTQ input (unzipped)
  - ``` --no-unal ``` no output for unaligned reads
  - ``` --mm ``` memory-mapped I/O for multiple and parallel uses of bowtie2 indexes

The output from ```bowtie2``` is in SAM format and will be piped to samtools to convert it to BAM format with ```-bS```. Logfiles are produced per Sample ID and per database. **Note**: In the bash script, we list all commands for each subdatabase and map against more databases than those listed here as an example. 

## 2. Filtering

We end up with large bam files that make computation slow and memory-intensive. Often the bam file header are too large to merge all bam-files together. The headers can be minimised (by deleting all entries that don't have associated mappings) using compressbam from metaDMG. Exemplary as before: 

```
cat "$SAMPLE_LIST" | parallel -j "$THREADSP" "for bam in $EUK_OUT/{}*.bam; do \
  /projects/wintherpedersen/apps/metaDMG_14jun24/metaDMG-cpp/misc/compressbam --threads 12 --input \$bam --output $EUK_OUT/$(basename \$bam .bam).comp.bam; \
done"
```
Function:
  - ```--input ``` bam input file
  - ```--output ``` output bam file 
  

Afterwards, we sort and merge all compressed bam files for one sample with ``` samtools ``` to one bam file. Afterwards we compress them again for easier handling downstream.

```
cat "$SAMPLE_LIST" | parallel -j "$THREADSP" "for bam in $EUK_OUT/{}*.bam; do \
  sorted_bam=\$MICROB_OUT/$(basename \$bam .bam).sorted.bam; \
  samtools sort -n -@ $THREADS -m 4G -o \$sorted_bam \$bam; \
cat "$SAMPLE_LIST" | parallel -j "$THREADSP" "samtools merge -@ $THREADS -n -f $EUK_OUT/{}.comp.sam.gz $EUK_OUT/{}*.sorted.bam"
cat "$SAMPLE_LIST" | parallel -j "$THREADSP" "/projects/wintherpedersen/apps/metaDMG_14jun24/metaDMG-cpp/misc/compressbam --threads 12 --input $EUK_OUT/{}.comp.sam.gz --output $EUK_OUT/{}.comp.bam"

done"
``` 
The next step is to complete a filtering step for each BAM file per sample ID. The first filter uses an EM-algorithm to decide on the best or set of best alignments (see: https://github.com/genomewalker/bam-filter)
``` 
cat "$SAMPLE_LIST" | parallel -j 1 "filterBAM reassign \
      --bam $EUK_OUT/{}.sort.comp.bam -t 4 -i 0 -A 92 -M 30G -m 5G -n 10 -s 0.0 \
      --squarem-min-improvement 0.001 --squarem-max-step-factor 2.0 \
      -o $EUK_OUT/{}.comp.reassign.bam &> $EUK_OUT/{}.comp.reassign.log.txt"

```
Function:
  - ```--bam ``` bam input file
  - ```-t ``` number of threads 
  - ```-i ``` number of iterations for the EM-algorithm 
  - ```-A ``` minimum of read ANI (Average Nucleotide Identity)
  - ```-m ``` maximum memory allocation for sorting (per thread)
  - ```-n ``` minimum read count per reference 
  - ```-s ``` scaling factor with 0.0, we retain all alignments
  - ```--squarem-min-improvment``` parameter adjustments for the EM-algorithm 
  - ```--squarem-max-step-factor``` parameter adjustments for the EM-algorithm
  - ```-o ``` output bam 

The filtering step for filterBAM provides statistic outputs for further analysis:
```
cat "$SAMPLE_LIST" | parallel -j "$THREADSP" "filterBAM filter \
      -e 0.6 -m 8G -t 12 -n 10 -A 92 -a 95 -N \
      --bam $EUK_OUT/{}.comp.reassign.bam \
      --stats $EUK_OUT/{}.comp.reassign.stats.tsv.gz \
      --stats-filtered $EUK_OUT/{}.comp.reassign.stats-filtered.tsv.gz \
      --bam-filtered $EUK_OUT/{}.comp.reassign.filtered.bam"
```
Function:
  - ```-e ``` minimum normalised entropy for a read (**Note: how is it calculated?)**
  - ```-m ``` maximum memory allocation per thread for sorting
  - ```-t ``` number of threads 
  - ```-n ``` minimum read count per reference
  - ```-A ``` minimum read ANI (Average Nucleotide Identity) 
  - ```-a ``` minimum average read ANI (Average Nucleotide Identity) per reference
  - ```-N ``` sort bam file by read names
  - ```--bam ``` input bam 
  - ```--stats ``` output statistics per reference in TSV format
  - ```--stats-filtered ``` output statistics per reference in TSV format
  - ```--bam-filtered ``` output bam after filtering

## 3. metaDMG taxonomic classification

The next step is to run the LCA (lowest common ancestor) algorithm to assign the reads to a taxonomic group. In principle, an LCA looks through all the references a read has mapped to (after filtering) and finds the lowest common taxonomical ancestor. For example, a read maps equally well to a position in the brown bear and the black bear genome. The LCA would classify the read at a genus level, as that would be the black and brown bears' common taxonomic group. 

The command will prepare all metaDMG standard output files (see: https://github.com/metaDMG-dev/metaDMG-cpp).
```
cat "$SAMPLE_LIST" | parallel -j "$THREADSP" "/projects/wintherpedersen/apps/metaDMG_28Nov24/metaDMG-cpp lca \
  --names $TAX_PATH_NCBI/taxdump/names.dmp \
  --nodes $TAX_PATH_NCBI/taxdump/nodes.dmp \
  --acc2tax <(zcat $TAX_PATH_NCBI/*.acc2taxid.gz) \
  --sim_score_low 0.95 --sim_score_high 1.0 --how_many 15 --weight_type 1 \
  --fix_ncbi 0 --threads 10 --filtered_acc2tax $EUK_OUT/{}.acc2tax \
  --bam $EUK_OUT/{}.sort.comp.reassign.filtered.bam --out_prefix $EUK_OUT/{}.sort.comp.reassign.filtered"
```
Function: 
  - ``` --names ``` NCBI taxonomy file
  - ``` --nodes ``` NCBI taxonomy file
  - ``` --acc2tax ``` NCBI taxonomy file (identifies the taxon ID for each assession number)
  - ``` --sim_score_low ``` minimum similarity score for an alignment to the reference (from 0 to 1)
  - ``` --sim_score_high ``` maximum similarity score for an alignment to the reference (from 0 to 1)
  - ``` --how_many ``` number of positions (from the 5' and the 3') included for damage estimation
  - ``` --weight_type ``` LCA weightning (0 = “count every alignment”: if a read maps to k references, each alignment gets full weight. This inflates counts for multi‑mappers. 1 = “fractional per‑read”: a read’s contribution is split across its k alignments, so the read contributes 1 in total. This avoids over‑counting multi‑mapped reads and is the recommended default.)
  - ``` --fix_ncbi ``` fixing NCBI taxonomy namees
  - ``` --threads ``` number of threads per run
  - ``` --bam ``` input bam file
  -``` --out_prefix ``` output prefix

The next step is to use the misincorporated bases files ({}.comp.reassign.filtered.bdamage.gz) to extract the observed DNA damage pattern (C->T on the forward strand and G->A on the reverse strand). 
```
cat "$SAMPLE_LIST" | parallel -j "$THREADSP" "/projects/wintherpedersen/apps/metaDMG_28Nov24/metaDMG-cpp dfit \
	  $EUK_OUT/{}.sort.comp.reassign.filtered.bdamage.gz --threads 6 \
	  --names $TAX_PATH_NCBI/taxdump/names.dmp \
	  --nodes $TAX_PATH_NCBI/taxdump/nodes.dmp \
      --showfits 2 --nopt 10 \
      --nbootstrap 20 --doboot 1 --seed 1234 --lib ds \
      --out_prefix $EUK_OUT/{}.sort.comp.reassign.filtered"
```
Function: 
  - ``` --threads ``` number of threads per run
  - ``` --names ``` NCBI taxonomy file
  - ``` --nodes ``` NCBI taxonomy file
  - ``` --showfits ``` definition of the beta-binomial model; here 2 ->  fits the model for both the forward (fw) and the reverse (bw) strands
  - ``` --nopt ``` ???
  - ``` --nbootstrap ``` number of bootstrap iterations
  - ``` --doboot ``` boolean for bootstrap
  - ``` --seed ``` random seed 
  - ``` --lib ``` specification of the library, either double-stranded or single-stranded 
  - ``` --out ``` output prefix

Next is merging the two outputs (the lca and the dfit statistics). The general input file is still the misincorporation file ending with ```.bdamage.gz```. 
```
cat "$SAMPLE_LIST" | parallel -j "$THREADSP" "/projects/wintherpedersen/apps/metaDMG_28Nov24/metaDMG-cpp aggregate \
	  $EUK_OUT/{}.sort.comp.reassign.filtered.bdamage.gz \
	 --names $TAX_PATH_NCBI/taxdump/names.dmp \
      --nodes $TAX_PATH_NCBI/taxdump/nodes.dmp \
      --lcastat $EUK_OUT/{}.sort.comp.reassign.filtered.stat.gz --dfit $EUK_OUT/{}.sort.comp.reassign.filtered.dfit.gz --out_prefix $EUK_OUT/{}.sort.comp.reassign.filtered.agg"
```
Function:
  - ``` --names ``` NCBI taxonomy file
  - ``` --nodes ``` NCBI taxonomy file
  - ``` --lcastat ``` metaDMG LCA output file ending in ```.stat.gz```
  - ``` --dfit ``` metaDMG dfit output file ending in ```.dfit.gz```
  
To make the output files workable for further analysis and plotting, they are being merged and converted into TSV (tab-separated) files. All the files per sample are now merged into one. We end with two output files. First, the metaDMG data files, which include the taxonomic assignments for the reads as well as the damage profiles per identified taxonomic taxa (**metadmg_data_final.tsv**). The second output is the statistics about said alignments per reference (**bam-filter_stats.tsv**). 

```
for file in  *.bdamage.gz.stat.gz ;  do echo "$file"; zcat "$file" | tail -n +2| awk -v filename="$file" '{print filename "\t" $0}' >> metadmg_data2.tsv ; done
zcat *.bdamage.gz.stat.gz | head -1 > metadmg_header.tsv
cat metadmg_header.tsv metadmg_data2.tsv > metadmg_data_final.tsv

for file in  *.comp.reassign.stats.tsv.gz  ;  do echo "$file"; zcat "$file" | awk -v filename="$file" '{print filename "\t" $0}' >> bam-filter_stats2.tsv ; done
grep 'reference' bam-filter_stats2.tsv -v > bam-filter_stats2_data.tsv
head -1 bam-filter_stats2.tsv > header.tmp
cat header.tmp bam-filter_stats2_data.tsv > bam-filter_stats.tsv
```

The two output TSV files are ready for further analysis!
