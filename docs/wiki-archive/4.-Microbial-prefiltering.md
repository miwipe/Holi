Microbial contamination is a common occurrence when classifying aeDNA samples. A way to minimise microbial contamination is explained below: 

## Mapping 
```
cat sample.list | parallel -j 3 "bowtie2 --threads 6 -k 1000 -D 15 -R 2 -N 1 -L 22 -i S,1,1.15 --np 1 --mp '1,1' --rdg '0,1' --rfg '0,1' --score-min 'L,0,-0.1' --mm --no-unal -x hires-organelles-viruses-smags/20240313/hires-organelles-viruses-smags.fas.gz -U {}.ppm.vs.d4.fq.gz | samtools view -bS - > {}.gtdb.bam 2> {}_gtdb.log.txt"
```

The microbial mapping is using the GTDB(https://gtdb.ecogenomic.org/), which is a curated database for microbial organisms. 
For computational time efficiency, the database is split into multiple parts. We map our data to each of the subdatabases; here, we portray one database for the example. 
Function: 
  - ```--threads ``` number of allocated threads
  - ``` -k ``` number of valid alignments per read, sorted based on alignment score (Note: every alignment after the first has a SAM 'secondary' bit (which equals 256) set in its FLAGS field (see: https://bowtie-bio.sourceforge.net/bowtie2/manual.shtml) 
  - ```-D ``` number of seed extensions that can fail 
  - ```-R ``` maximum number of reseed attemps
  - ```-N ``` number of mismatches allowed in a seed
  - ```-L ``` length of the seed substring 
  - ```-i ``` function to set the interval between seed substrings
  - ```--np ``` penalty for ambiguous characters in read or reference
  - ```--mp ``` max and min mismatch penalties
  - ```--rdg ``` read gap open and extend penalties
  - ```--rfg ``` reference gap open and extend penalties
  - ```--score-min ``` function to set minimum alignment score needed
  - ```-t ``` wall-clock time output
  - ```-x ``` bowtie2 index prefix
  - ``` -U ``` FASTQ input (unzipped)
  - ``` --no-unal ``` no output for unaligned reads
  - ``` --mm ``` memory-mapped I/O for multiple and parallel uses of bowtie2 indexes


All parameter explanations in more detail can be found in the Bowtie2 manual(https://bowtie-bio.sourceforge.net/bowtie2/manual.shtml). The specific parameters set for mismatches, penalties and seeding combine to allow a linear mapping strategy with 92% similarity between the reference and the read. 

The output from ```bowtie2``` is in SAM format and will be piped to samtools to convert it to BAM format with ```-bS```. Logfiles are produced per Sample ID and per database. 

Because we have our GTDB database in multiple chunks, we need to sort and merge the BAM files into one. 
```
cat sample.list | parallel -j 3 "for bam in {}.gtdb.*.bam; do \
    sorted_bam=$(basename \$bam .bam).sorted.bam; \
    samtools sort -@ 10 -m 4G -o \$sorted_bam \$bam; \
done"

cat sample.list | parallel -j 3 "samtools merge -@ 10 -f {}.gtdb.merged.bam {}.gtdb.*.sorted.bam"

```
The goal is to extract all reads from the original fastq file that map to/are assigned to the GTDB taxa Virus, Bacteria or Archaea, with a certain amount of similarity. Our bash script implemented two ways of identifying these reads. 

### 1. LCA assignment with metaDMG
The first way to identify all reads that mapped to the GTDB and were classified to from the taxa Virus, Bacteria or Archaea is to use an LCA assignment with metaDMG. 

```
cat "$SAMPLE_LIST" | parallel -j 3 "/projects/wintherpedersen/apps/metaDMG_28Nov24/metaDMG-cpp lca \
	  --names '$TAX_PATH_BAC'/names.dmp \
	  --nodes '$TAX_PATH_BAC'/nodes.dmp \
	  --acc2tax '$TAX_PATH_BAC'/../hires-organelles-viruses-smags.acc2tax.gz \
	  --sim_score_low 0.92 --sim_score_high 1.0 --how_many 15 --weight_type 0 \
	  --fix_ncbi 0 --threads 10 \
	  --bam {}.gtdb.merged.bam --out_prefix {}"
```
Function:
  - ```--names ``` NCBI names file, available via the NCBI taxdump, needs to represent the DB
  - ```--nodes ``` NCBI nodes file, available via the NCBI taxdump, needs to represent the DB
  - ```--acc2tax ``` NCBI accession to taxid file, available via the NCBI taxdump, needs to represent the DB
  - ```sim_score_low ``` The lower limit allowed for similarity between the read and the reference
  - ```sim_score_high ``` The upper limit allowed for similarity between the read and the reference
  - ```--how_many ``` Number of bases reported for the damage estimation
  - ```--weight_type ``` Weighted LCA 
  - ```--fix_ncbi ``` Fix NCBI taxonomy entries
  - ```--threads ``` Number of threads given 
  - ```--bam ``` bamfile input 
  - ```--out_prefix ``` output prefix

Following the LCA assignment, we can extract all reads that are assigned to Archaea, Virus or Bacteria and extract them from all available reads to get the reads only that have not mapped to the GTDB or were assigned to a eukaryotic clade.
 
```
	cat "$SAMPLE_LIST" | parallel -j "$THREADSP" "zgrep -i -E 'Archaea|virus|bacteria' $MICROB_OUT/{}.lca.gz | cut -f1 > $MICROB_OUT/{}.bact_reads.txt" 

	cat "$SAMPLE_LIST" | parallel -j "$THREADSP" "seqtk subseq {}.ppm.vs.d4.fq.gz $MICROB_OUT/{}.bact_reads.txt | gzip > $MICROB_OUT/{}.bact_reads.fq.gz"

	cat "$SAMPLE_LIST" | parallel -j "$THREADSP" "zcat {}.ppm.vs.d4.fq.gz | awk 'NR%4==1 {print substr($0, 2)}' > $MICROB_OUT/{}.all_reads.txt"

	cat "$SAMPLE_LIST" | parallel -j "$THREADSP" "comm -23 <(sort $MICROB_OUT/{}.all_reads.txt) <(sort $MICROB_OUT/{}.bact_reads.txt) > $EUK_OUT/{}.euk_reads.txt"

	cat "$SAMPLE_LIST" | parallel -j "$THREADSP" "seqtk subseq {}.ppm.vs.d4.fq.gz $EUK_OUT/{}.euk_reads.txt | gzip > $EUK_OUT/{}.euk.fastq.gz"
```

Optionally, one can add a filterBAM step before the LCA assignment. Using ```bamfilter reassign``` and/or ```bamfilter filter``` would make the filtering more strict, meaning one would be left with more reads for the eukaryotic mapping.

### 2. Mapping and taxonomic identification with getRtax
The second option is to identify all reads to Archaea, Virus and Bacteria right after mapping with the tool getRtax(https://github.com/genomewalker/get-reads-taxonomy). This tool needs a TSV file that links the accession number to their taxonomy. 

```
parallel -j "$THREADSP" "getRTax --bam '$MICROB_OUT'/{}.bam -T $TAX_PATH_BAC/ -r '{\"domain\":[\"d__Bacteria\", \"d__Archaea\", \"d__Viruses\"]}' --threads 8 --unique --only-read-ids -p '$RESULT_PATH'/{}.bact_reads.txt" :::: "$SAMPLE_LIST"

	parallel -j "$THREADSP" "zcat $MICROB_OUT/{}.bact_reads.txt* > $MICROB_OUT/{}.bact_reads_all.txt" :::: "$SAMPLE_LIST"

	parallel -j "$THREADSP" "seqtk subseq {}.ppm.vs.d4.fq.gz $MICROB_OUT/{}.bact_reads_all.txt | gzip > $MICROB_OUT/{}.bact_reads.fq.gz" :::: "$SAMPLE_LIST"

	parallel -j "$THREADSP" "zcat {}.ppm.vs.d4.fq.gz | awk 'NR%4==1 {split(substr(\$0, 2), a, \" \"); print a[1]}' > $MICROB_OUT/{}.all_reads.txt" :::: "$SAMPLE_LIST"

	parallel -j "$THREADSP" "sort $MICROB_OUT/{}.all_reads.txt > $MICROB_OUT/{}.all_reads.sorted.txt" :::: "$SAMPLE_LIST"
	parallel -j "$THREADSP" "sort $MICROB_OUT/{}.bact_reads_all.txt > $MICROB_OUT/{}.bact_reads_all.sorted.txt" :::: "$SAMPLE_LIST"


	parallel -j "$THREADSP" "comm -23 $MICROB_OUT/{}.all_reads.sorted.txt $MICROB_OUT/{}.bact_reads_all.sorted.txt > $EUK_OUT/{}.euk_reads.txt" :::: "$SAMPLE_LIST"

	
	parallel -j "$THREADSP" "seqtk subseq {}.ppm.vs.d4.fq.gz $EUK_OUT/{}.euk_reads.txt | gzip > $EUK_OUT/{}.euk.fastq.gz" :::: "$SAMPLE_LIST"
```
The extraction of the eukaryotic and unmapped reads to create a new FASTQ file for the eukaryotic mapping stays the same as in the LCA assignment approach. With the new FASTQ file, we continue our mapping as described in Taxonomic Classification.
